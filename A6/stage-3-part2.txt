  predicate function on it. If it does not pass, move onto the next record. If  
  it does, define a new empty output record and set each attribute using the    
  set () function and the output of the corresponding projection function.      
  Lastly, call recordContentHasChanged (), and append () to the output. A few   
  more key points:                                                              
  1. The selection predicate stems from the selectionPredicate string input,    
  which specifies in the prefix format what the predicate should do. This       
  string input is then passed into the compileComputation() function on a       
  MyDB_Record, to define a function that evaluates this predicate on the record 
  it is defined on.                                                             
  2. The predicate is compiled against the record that is used to define the    
  predicate function (i.e. the one used to call compileComputation()).          
  3. The output record should be defined as a new empty record of the output    
  table, which you can assume to have a schema that matches the projections     
  input. The projections input list specifies, in order, the computations to    
  perform to create each attribute in the output record. You use each           
  projection string to compileComputation() on the record you are iterating     
  over, which returns a function that returns the projection output. You then   
  use this output to set the corresponding attribute in the output record.      
  4. You do not need to ensure that the output’s table schema matches the       
  projections, and you can assume that they always match in number and type. No 
  need to do any checks for this.                                               
  5. recordContentHasChanged () should be called every time before you append   
  an output record to an output table. This is because you change the values of 
  the record’s attributes with set ().

     1. inRec = input->getEmptyRecord().

     3. Compile each projection against inRec.
     4. outRec = output->getEmptyRecord() (once).
     5. it = input->getRangeIteratorAlt(low, high); then while (it->advance()):
        - getCurrent(inRec);
        - skip the record if the predicate is false;
        - set each output attribute from its projection;
        - recordContentHasChanged(); append.

     Implementation (after the tests are approved)

     In SortMergeJoin.cc, run() plus a file-local helper. Existing code reused:
     buildItertorOverSortedRuns(runSize, table, comparator, lhs, rhs, pred)
     (Sorting.h), the combined-schema plus buildFrom pattern (ScanJoin.cc), and
     anonymous pinned pages MyDB_PageReaderWriter(true, *mgr) with
     getIteratorAlt(vector<pages>) (MyDB_PageReaderWriter.h).

     1. buildComparator(func lhsF, func rhsF, MyDB_AttTypePtr type). Returns a
        lambda for lhsF() < rhsF(), comparing as int, double or string depending
        on type. This is the same pattern as
        MyDB_BPlusTreeReaderWriter::buildComparator, but it compares computed
        values instead of attributes. The type comes from
        record->getType(computation).
     2. Sort both sides.
        - Left: records lhsL/rhsL from leftTable->getEmptyRecord(). The
          comparator compares equalityCheck.first compiled on each. Call
          buildItertorOverSortedRuns(runSize, *leftTable, cmp, lhsL, rhsL, 
          leftSelectionPredicate).
        - Right: the same, with equalityCheck.second and
          rightSelectionPredicate.
     3. Separate records for the current rows. leftRec and rightRec are separate
        records, so the sort iterators' internal lhs/rhs are never disturbed
        (your point 3). Compile leftKey = equalityCheck.first on leftRec and
        rightKey = equalityCheck.second on rightRec. Build two comparators:
        leftLess (left key < right key) and rightLess (right key < left key).
     4. Combined record. Build a schema with the left attributes followed by the
        right ones, then a combinedRec built with buildFrom(leftRec, rightRec).
        Compile finalPred and the projections on combinedRec. Create outRec
        once.
     5. Merge loop. Advance both iterators once. While both still have a record:
        - If leftLess, advance left. Else if rightLess, advance right.
        - Otherwise the keys are equal:
          - Collect the left group. Copy every left record with this key into a
            list of pinned anonymous pages. Start with one page and add a page
            whenever the current one is full.
          - Join the right group. For every right record with the same key,
            iterate over the saved left records (getIteratorAlt(groupPages) into
            leftRec). For each one, evaluate finalPred on the combined record;
            if true, set the output attributes from the projections, call
            recordContentHasChanged(), and append.
          - Clear the group pages and continue. The iterators are now on the
            first record after each group, or exhausted.
        - Because the whole right group is processed before the loop checks
          again, it no longer matters which side runs out first.
